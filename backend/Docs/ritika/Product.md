# 📦 Product Module

## 1. Overview

The **Product Module** manages the complete lifecycle of products in the e-commerce system.  
It is responsible for product creation, updates, catalog exposure, pricing, inventory tracking, and image management.

The module is divided into **Admin APIs** and **Public Catalog APIs**, ensuring **security, clarity, and scalability**.

All sensitive fields such as **Slug** and **SKU** are **fully controlled by the backend** to maintain data integrity and SEO consistency.

---

## 2. Responsibilities

### Core Responsibilities
- Create and manage products (admin-controlled)
- Generate SEO-friendly product slugs automatically
- Generate immutable system SKUs
- Manage product pricing and stock
- Handle product images and primary image selection
- Expose products to public catalog with pagination and filtering

### Explicitly NOT Allowed
- Frontend-controlled slug or SKU
- Editing SKU after product creation
- Direct database ID manipulation by frontend
- Public (customer) product modification

---

## 3. Database Design

### Products Table

Stores product-level information.

| Column | Description |
|------|-------------|
| ProductId | Unique product identifier |
| CategoryId | Associated category |
| Name | Product name |
| Slug | SEO-friendly unique identifier |
| Description | Full product description |
| ShortDescription | Summary description |
| Price | Product price |
| StockQuantity | Available stock |
| SKU | System-generated product code |
| IsActive | Product availability |
| CreatedAt | Product creation time (UTC) |
| UpdatedAt | Last update time |

### Constraints & Rules
- `Slug` is **NOT NULL + UNIQUE**
- `SKU` is **NOT NULL + UNIQUE**
- `CategoryId` is enforced via foreign key
- SKU is immutable once created

---

## 4. Slug & SKU Strategy

### Slug Rules
- Generated automatically from product name
- Lowercase, hyphen-separated
- Incremented if duplicate

Examples:
- iphone-15-pro
- iphone-15-pro-1
- iphone-15-pro-2


### SKU Rules
- Generated by the backend
- Never accepted from client
- Never updated
- Used for internal tracking

Example: PRD-2025-A9F3C2

## 5. API Endpoints

### Admin APIs (Protected)

Base Route:
- /v1/admin/products


---

### Create Product
- **POST** `/v1/admin/products`
- Content-Type: `multipart/form-data`

**Behavior**
- Slug generated automatically
- SKU generated automatically
- Product images uploaded
- One primary image selected
- CategoryId must be valid

---

### Get Product by ID (Admin)
- **GET** `/v1/admin/products/{id}`
- Returns full product details including images

---

### Get Products (Admin List)
- **GET** `/v1/admin/products`
- Supports pagination and filtering

**Query Parameters**
- `search`
- `categoryId`
- `onlyActive`
- `page`
- `pageSize`

---

### Update Product
- **PUT** `/v1/admin/products/{id}`
- Content-Type: `multipart/form-data`

**Rules**
- Slug is regenerated **only if name changes**
- Slug is NOT accepted from frontend
- SKU is never updated
- Images can be added or replaced

---

### Delete Product
- **DELETE** `/v1/admin/products/{id}`
- Deletes the product record
- Returns 404 if product does not exist

---

## 6. Catalog APIs (Public)

Base Route:
- /v1/catalog/products

These APIs are **read-only** and accessible to customers.

---

### Get Products (Catalog)
- **GET** `/v1/catalog/products`

**Query Parameters**
- `categoryId`
- `search`
- `page`
- `pageSize`

**Behavior**
- Returns only active products
- Includes primary image URL
- Paged response

---

### Get Product Details
- **GET** `/v1/catalog/products/{slugOrId}`

**Behavior**
- Accepts product slug OR numeric ID
- Returns full product details
- Includes all product images

Examples:
- /v1/catalog/products/iphone-15-pro
- /v1/catalog/products/101


---

## 7. Validation Rules

### Product Creation Validation
- CategoryId must exist
- Price must be greater than zero
- Stock quantity cannot be negative
- Product name is required

### Product Update Validation
- Product must exist
- Name is required
- Price must be valid
- Slug uniqueness enforced by database

Validation is implemented using **FluentValidation**.

---

## 8. Design Decisions & Best Practices

### Why slug is backend-generated
- Ensures SEO consistency
- Prevents URL tampering
- Avoids duplicate conflicts

### Why SKU is immutable
- Required for accounting & logistics
- Prevents tracking inconsistencies

### Why admin and catalog APIs are separated
- Improves security
- Simplifies frontend consumption
- Allows independent scaling

### Why database enforces uniqueness
- Prevents race-condition issues
- Guarantees data integrity
